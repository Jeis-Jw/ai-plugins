## 범위와 완료 기준

같은 rollback unit으로 Studio와 관련 실행 계약·테스트·문서를 수정한다. executable-criteria audit, targeted/delta QA, hard review 뒤 final-grade root QA 1회, batch evidence, tree/digest equivalence 기반 reuse와 strict invalidation, 단일 integration evidence digest 참조, 최소 telemetry를 검증한다. artifact/context quality hard floor, 독립 hard review, production public surface acceptance, worktree 격리, budget corpus, strict-integrity, single executor, stale-evidence invalidation과 owner gate는 유지한다. 새 runtime·broker·state store·GitHub issue tree·push·release·외부 공개는 제외한다. 완료 조건은 수치와 코드 경로의 원인 설명, executable reuse/invalidation 및 final QA/batch 회귀 테스트, blocking 0 approved review, clean local main 통합·커밋, before/after scorecard다.

아래 후속 revision은 이후 사용자 정정으로 폐기됐으며 역사적 작업안으로만 보존한다.

- Studio는 `risk`, `topology`, `persistence`, `delivery`, `review`, `evidence`를 분리해 direct/single-run/graph/audit route와 예상 ceremony를 투영하고, close 시 `ready_next=[]`와 commit/push/release 상태를 분리한다.
- task-worker는 single-run, 완전한 physical preflight, content-addressed evidence reuse, final-QA batch, 단일 `--state-root`, 단일 child root coalescing을 first-class API로 제공한다.
- session-review는 target ref 변경만으로 reviewer를 fresh 처리하지 않고, diff base/target·recording/strength·confirm round·fast canonical state를 검증한다.
- 개발은 focused regression, reviewer는 finding/delta, frozen candidate는 final full-QA batch 1회를 기본으로 하며 source/test/config 변경만 QA와 confirm을 무효화한다.
- 통합 회귀는 high-risk single leaf, real graph, invalid evidence setup, review continuity, receipt closeout 다섯 scenario를 모두 포함한다.

실행 graph는 owner 경계와 직접 dependency만 반영한다. TW1(task-worker)과 SR1(session-review)은 독립 실행하고, ST1(Studio)은 두 계약에 의존하며, root integration이 shared scenario·version parity·final QA·독립 hard review를 소유한다. 파일이나 개별 결정단위로 leaf를 추가하지 않는다.

### 2026-08-14 사용자 정정 — 최신 실행 계약

- Studio는 특정 plugin의 목록, 적합성 규칙, CLI 순서와 lifecycle을 내장하지 않는다. host가 제공한 skill catalog의 `name + description`으로 후보를 고르고, 선택한 `SKILL.md`를 끝까지 읽어 그 계약을 따른다.
- `.studio.yml`의 work/review/delivery command는 user policy다. `auto`는 description match가 필요한 선호 후보, `always`는 exact 사용자 선택, `never`는 route 비활성이다. 미설정 work/review는 host의 정상 skill selection을 사용하고 delivery는 명시적으로 켠 경우에만 실행한다.
- 이전 revision의 Studio 자체 work-shape heuristic과 `select-work` projection은 폐기한다. task-worker가 언제 유용한지는 task-worker의 공개 plugin/skill description이 설명하고 Studio는 그 설명을 현재 미션과 대조한다.
- task-worker first-class single-run 계획은 폐기한다. 1-node 실행은 기존 graph 축소나 명시적인 durable resume·외부 handoff를 위한 호환 경로로만 유지하며, 자체 state/evidence/resume/cleanup 약점만 독립 개선한다.
- session-review는 task-worker 사용 여부와 무관한 독립 review 도구로 유지하고 reviewer continuity와 자체 상태 검증만 개선한다.
- 각 plugin/skill은 frontmatter description에 무엇을 하고 언제 쓰는지를 공개한다. 이미 충분한 설명은 유지하고, 선택 경계를 설명하지 못한 entry/operation skill만 보강한다.
- 세 플러그인을 하나의 shared lifecycle이나 결합 acceptance scenario로 묶지 않는다. 최소 public interface 호환성 외에는 각 플러그인의 focused regression으로 검증한다.
