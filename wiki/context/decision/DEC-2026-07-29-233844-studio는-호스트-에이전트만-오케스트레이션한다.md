## 결정

Studio의 제품 경계를 역할 선택, 작업 배정, 호스트 서브에이전트 소집, 메시지 중계, 결과 회수, 리뷰·재작업 라우팅으로 제한한다. 에이전트 실행, sandbox, 인증, tool inventory, command permit, worktree, review episode, 지식 저장은 각 호스트 및 전용 플러그인에 위임한다.

## 취지

Codex와 Claude Code에서 동일한 Studio 개념을 사용하되 호스트의 native agent lifecycle을 그대로 이용하여 실패면과 유지보수 비용을 줄인다.

## 배경

Studio 0.11.1의 Codex persistent admission이 sandbox에서 loopback listen EPERM으로 crew 생성 전에 실패했다. 조사 결과 Studio가 app-server, binary pinning, auth home, loopback capture, persistent store와 실행·검수 계약까지 자체 소유하고 있었다.

## 고려한 대안

기존 custom persistent runtime을 보수하거나 호스트별 독립 런타임을 계속 유지하는 대안을 검토했다.

## 트레이드오프

호스트별 agent API 차이는 얇은 adapter에서 처리한다. 호스트가 제공하지 않는 capability는 unsupported로 보고하며 Studio가 비공식 runtime으로 보완하지 않는다.

## 재평가 조건

Codex나 Claude Code가 서브에이전트 lifecycle을 제공하지 않게 되거나, Studio 자체 runtime이 반드시 필요한 독립 배포 제품으로 범위가 변경될 때 재평가한다.
